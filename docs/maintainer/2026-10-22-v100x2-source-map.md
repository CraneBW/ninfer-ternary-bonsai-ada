具体数学/存储检查：

- **split-KV reducer：** donor 先合并各 split 的 `partial_m`/`partial_l`，将共享的指数权重存入 shared `weights`，按升序把 8 个（特定五查询/长窗为 16 个）split 的输出向量协同读入 shared `values`，再保持 split 升序累加。**donor 参数 `partial_acc` 为 BF16，本机 `partial_acc` 为 FP32**；直接照抄其签名、cast 或归约树会改变本机边界。本机已共享权重，无需重复实现这一部分。
- **INT8 QK：** donor kernel 的 K/V 从 INT8-G64 codes + FP16 scales 解码成 FP16 fragments；QK 在两个 8-key score tile 上计算后共享，PV 分配在多个 dimension warps。源端另有 `InlineQK`、`Fp32Pv`、`SharedSoftmax` 模板分支，`Warps == 8` 才启用 `SharedSoftmax`；并非所有 T/上下文都走同一个 kernel。实验性 FP32 PV 和长窗 softmax 不能同默认路径混算。
- **GDN pre-norm：** donor 用 warp FP32 平方和/`rsqrtf(sum+eps)` 生成**FP32** normalized Q/K，然后交给保持 FP32 state 的顺序 recurrence。当前主仓在 `T_full > 0` 且需归一化时，先经 `l2norm` 写入 **BF16** Q/K，再走 chunked path，余数 tail 交给 recurrent；将 donor FP32 buffer 与顺序路径照搬既会改变舍入点，也可能丢失当前 chunked prefill 的吞吐优势。源端自报 3072-token TP2 workspace 为 24 MiB，仅代表该几何，不能视为本机实测占用。

## 4. 对 SM89 GSQ 的采用决策

| 子项 | 适合进一步评估 | 目前不适用、不能宣称 |
|---|---|---|
| 同权重下 split-vector cooperatively staged reduce | 只在真实长历史 `active_splits` 较高且 reducer 成为热核时，保留本机 FP32 partials/累加顺序，比较不同 `DChunk/SplitTile` | 直接套 donor BF16 partial、重复实现 shared weights，或把 donor 局部 Op 收益算成 213K TTFT 收益 |
| QK / probabilities 跨 PV warp 复用 | 面向本机 `QHeads=24`、真实 INT8-G64 几何，抽取通用数据复用与分工，用 SM89 已有 primitives 重写 | Volta `mma.sync.m8n8k4`/QPN、SM70 寄存器与 shared tile、TP2 的 12-Q-head 特化、原样拷贝 launcher |
| GDN FP32 Q/K prepare | 先确认当前 BF16 预归一化与 normalized Q/K 复算是否真实瓶颈；如评估 FP32 staging，保持 FP32 state 和调用者 workspace 生命周期/身份一致 | 称作本机从未有预归一化；默认用 donor 顺序 recurrence 替换 chunked；以短模型 PPL 或源码注释承诺长历史完全等价 |
| Volta Long Attention、NVFP4/CUTLASS、TP2 PCIe transport | 仅作为非目标背景，必要时另立独立数学或通信资格 | 向单卡 SM89 复制 SM70-only kernels、双卡 P2P、NVIDIA NVLink 假设；移植 QUASAR NVFP4 权重或采信其 198/230 tok/s 数字 |

注意固定 README 的 **TP2/MTP4/180K**（首段对照与 TUI 默认配置）与 design 第 16 行保留的“当前 README 主档 180000/MTP3”**存在口径差异**；本记录只以固定 SHA 的 README 为本次观察，不倒写 design，也不依据任一配置推断本机已验证。README 的较大 262144 容量与 85K 输入跑分也不是同一个概念；不同 Vision、MTP 和实验 flags 的指标不可合并。

若 S4 选用上述思路，最低验收边界是：在本机实际 GSQ attention/GDN 路由上保留 cache codec/页位置/完整历史、可见 BF16/FP32 cast 与 GDN state 转移；用独立 FP32/FP64 Op oracle 验证真实 N/K/T 与跨页/短尾/长窗；先确保原 213K 问题正确，再以同 binary、200W 的实际整模型对照确认收益。仅对已定位的热核使用有界 NCU。本记录不赋予任何候选“已通过”状态。
