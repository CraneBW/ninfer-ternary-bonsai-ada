# v1.0.0 — 原生 GSQ、KVMem 状态恢复与单卡流水

2026-10-21。首个 SemVer 主版本，源代码发布；模型权重、编译产物、KV 后备文件与本机 profiler 数据独立保存。

## 本版交付

- 原生 C++20/CUDA Engine 使用 `.ninfer` v3，直接执行现有 Qwen3.8-27B GSQ 的混合 GGUF 量化块；GGML CUDA 产品与本项目模型、状态、调度和协议层配合工作。
- KVMem 的逻辑上下文、设备工作集和归档容量解耦；不可变 K 来源、owner/generation/pin/event 约束、选页视图的 GDN/KV 联合重建与原问题回放接入真实服务。支持显式 global Host KV 0，独立 KVMem 归档和 StateImage 仍存在。
- 页搬运支持有界异步拆分、完成后发布和失败排空；source-K 支持层批处理、H2D 子批与双槽读前。普通搬运默认仍为 sync，读前显式开启；本版不认领新的物理 NVMe 冷读加速。
- SM89/66SM 调优包含 INT8 prefill 流水、三格式 MMQ 路由、decode reduce-scatter、完整 K/J16 的 BF16 写回，以及保持 BF16 舍入边界的 SiLU/down 激活量化融合。
- 固定 MTP 扩展至 K15/T16，帧、AR、KV 预算、接受前缀与 Graph 一致适配。默认推荐分为已测短档 K7 和已测 32K 长档 K15；adaptive/lookup 仍限制到 K7，没有自动跨档切换。
- 修复 K15/INT8 启动档位由 Prompt 切换到 8+8 SmallT 时的 Graph 拓扑更新失败：仅对 CUDA 明确返回的 topology-changed 先构建替代 executable，成功后替换；其它错误继续报告，失败时保留旧 executable。复用 ninfer-all 的重实例化思路并收窄触发条件。
- README 根据当前源码、接口和实际结果重新编写；CMake 软件版本为 1.0.0。专用 Bench 的帮助与参数范围同步，旧 invalid-K8 断言改为 invalid-K16。

## 整体性能对照

全部为最终同一 `ninfer_bench`、同一模型与固定 corpus；RTX 4070 Ti SUPER 16 GiB、SM89/66SM、INT8/chunk512、C1、Graph、optimized proposal head。每档按 ABC/CBA/ABC 运行九个独立进程，每进程一次 warmup、一次测量；短、长共18进程。每档九次完整129个输出IDs一致。

A 为同一二进制显式关闭六项性能开关的回退参考；B 开启六项且固定 K7；C 在 B 上开启新组合并固定 K15。A 的定义见[完整方法](v1.0.0/overall-performance.md)，不表示某个旧发行版或当前程序默认配置。

| 工作负载 | 推荐显式配置 | prefill tok/s：A → 推荐 | decode tok/s：A → 推荐 | 配对吞吐增幅中位：prefill / decode |
|---|---|---:|---:|---:|
| pp4096 + tg128，ctx8192 | B / K7 | 1882.90 → 1973.53 | 186.59 → 189.75 | +5.23% / +0.76% |
| pp32768 + tg128，ctx36864 | C / K15 | 1683.13 → 1838.12 | 173.41 → 192.92 | +9.58% / +11.78% |

短档 B/A 的 prefill 三对均正，decode 两正一负，后者不作稳定加速结论。长档 C/A 两项三对均正。C/B 的 decode 在短档退化15.18%，长档提升10.22%且三对均正，故保留两个显式配置。没有从两个输入长度推导通用切换阈值，也没有将分散轮次的收益相加。

表内绝对吞吐为每配置三次中位数，百分比为逐组比值的中位数，二者计算口径不同。[完整原值、命令、环境与输出IDs](v1.0.0/overall-performance.json)支持重算全部三组比较；它们是整模型结果，不能拆分认领每项算子的贡献。

## 支持边界与后续

- 256K原题与图像/视频有此前功能版本的独立记录；本轮没有把它们重新认证为K15配置。当前真实验收以本页工作负载为准。
- 先前P4 54/54正确，但深轮async约0.54%的session wall改善未达10%默认采用门槛；sync继续默认。本版未重跑P4，也未宣称async普遍更快。
- 原位置/query-only重放实验仍关闭，其已知原题失败未解除；本版推荐canonical路径。
- 理想MTP权重pass上限、寄存器减少、LOCAL0或单项微基准均不视为整模型收益或设备最优证明。
- 沿用真实模型、固定原题及最小必要验证；后续TTFT重点仍是减少真实历史重建、物理冷读与大批搬运开销。

源码主要依据为当前NInfer、GGML和KVMem/ActKV/Strata/Sync相关实现，保留各自归属及许可证。Graph恢复参考[ninfer-all](https://github.com/iamwavecut/ninfer-all)。构建与两个显式运行入口见[README](../../README.md)，运维见[CUDA服务规程](../maintainer/cuda-service-operations.md)。
